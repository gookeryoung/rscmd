- 实测口径：本机 Windows 11 + `cargo xtask check` / `check-cov`（TOTAL 96.86%，1849 行 / 58 行未覆盖，2026-11-16 实测）。
- 性质：**本文件只出方案，不修改源码、不提交、不推送**。新文件与 `docs/infrastructure-plan.md` 并存：旧文件是 P0/P1 的初版计划，本文件是完成 P1 之后的**全量对照与剩余路线**，两者冲突时以本文件为准。

## 0. 结论先行

| 维度 | fcmd | rscmd 现状 | 结论 |
|---|---|---|---|
| 基础件 | 15 个领域自成体系（信封/退出码/schema/参数投影/发现/清单/任务图/画像/发布） | 15 项中 **9 已具备、1 无需补齐、4 部分具备、1 缺失** | 骨架已对齐；剩余差距集中在 **doctor 覆盖面、日志落盘、目录约定、工具接线面**，不在契约层 |
| 工具数量 | 11 类约 90 个工具 + 14 个 GUI 应用 | 3 个（`case` / `wc` / `json_fmt`） | 工具数量是最大数量差，但**只应按「小模型高频 + 零/低依赖 + 跨平台一致」补**，本轮目标新增 8–11 个（总数 11–14） |
| 门禁 | Makefile + 95% 覆盖率 + ruff/pyrefly/tox/prek | xtask 单入口 + 95% 覆盖率 + 三平台 CI + 三平台 wheel | 能力不输，**不需要补** |
| 契约风险 | 无版本化破坏先例 | `rscmd-schema/1` 刚落地 | 后续任何信封字段变更都要走 §5 决策 |

一句话：**不要按 fcmd 的工具清单做数量对齐，按「基础件收口 → 零依赖工具 → 结构化数据 → 系统只读 → 网络」五步补，先补能提高模型成功率的工具，再谈目录与缓存。**

- 验收：`--json` 下 envelope 字段集合被契约测试逐字段固定；`--quiet` 不吞错误。
- 估级 S ｜ 优先级 P3

### 2.2 退出码与 kind 映射 —— 已具备

### 2.3 schema 自描述 —— 已具备

- fcmd：`cli/_schema.py`（99 行）+ `fcmd-schema/1`，含工具元数据、子命令、GUI 标记。
- 现状证据：`envelope.rs:10`；`rscmd schema` 输出 `version/tools/builtins/global`；`schema/*.json` 五份生成物；`docs/schemas.md`、`docs/global-args.md`、`docs/tools.md` 由 `xtask gen-docs` 生成并被 `docs-check` 校验。
- 缺口：`rscmd tools` 仍是裸数组，未套版本信封（与 `schema` 不一致）；`schema` 未包含工具别名（`cli.rs` 已支持别名，schema 里没有）。

- 验收：`rscmd tools --json` 有 `schema` 版本字段；`schema` 中每个工具能看到别名；契约测试覆盖。
- 估级 S ｜ 优先级 P2（**属契约变更，见 §5-D5**）

### 2.4 参数校验与默认值 —— 部分具备

- fcmd：`core/toolkit/args.py:49-108`（`ToolSpec`）、`:158-217`（签名→argparse 投影，含 `--json`/`--from` 与类型映射）。
- 现状证据：clap derive + `schemars` 生成 JSON Schema；`args.rs:57` 的 `global_schema()`；`xtask::schema_check` 强制生成物最新。
- 缺口：(a) `--dry-run`/`--confirm` 只是 `ToolCtx` 字段，**没有框架级强制**，工具可以无视；(b) 工具级默认值只写在 clap 里，`docs/global-args.md` 只覆盖全局参数；(c) 没有"危险操作必须 confirm"的约定文档。
- 建议：在 `ToolCtx` 增加 `require_confirm(action: &str) -> Result<(), RscmdError>`（`confirm=false` 时返回 `CONFIRM_REQUIRED`，kind=usage），并在 `docs/tools.md` 生成列里补 `side_effects`；**不改已有工具行为**，仅新工具使用。
- 验收：新单测覆盖 `confirm=true/false/dry_run=true` 三种分支；`side_effects != none` 且未加 confirm 的工具被 `registry-check` 拒绝。
- 估级 M ｜ 优先级 P1

### 2.5 日志与 verbose —— 部分具备

- fcmd：`console.py` 的 `print_error`/`print_verbose`；无 `--log-file`、无 tracing、非 TTY 无统一降级。
- 现状证据：`--verbose` 已落地（`render.rs:13` 前置 trace 写 stderr）；`--quiet`/`--json` 语义互不污染；无日志文件、无 `tracing`/`env_logger` 依赖（`Cargo.toml` 可验证）。
- 缺口：CI/代理场景无法留档；verbose 只有一行 `tool/elapsed`，没有阶段与关键参数；日志中可能夹带路径等敏感信息，没有脱敏口径。
- 建议：`--log-file <PATH>`（新增，写 NDJSON：`ts/tool/phase/elapsed_ms/exit_code`），默认关闭；`--verbose` 保持现状；不引 `tracing`，用已有 `fs::atomic_write` 追加写。
- 验收：`--log-file` 后文件每行可 `serde_json` 解析；`--quiet --log-file` 组合下 stdout 仍为空；不写文件时零开销。
- 估级 M ｜ 优先级 P2

### 2.6 超时与中断 —— 已具备

- fcmd：`core/execution/task_runner.py:431-444`（`asyncio.wait_for` 超时）、`:411-420`（`KeyboardInterrupt`→`INTERRUPTED`）。
- 现状证据：`args.rs:18`（`--timeout` 秒，0=不限制）、`ctx.rs:45`（`timeout_or`）、`main.rs:7-13`（SIGINT→`Outcome::interrupted`→130）、`errors.rs`（`TIMEOUT`/`INTERRUPTED`）。
- 缺口：**没有工具消费 `ctx.timeout`**（当前 3 个工具都是纯内存计算），`proc`/`net` 的默认超时仍由调用方硬编码；`bounded_parallel_map` 未接 `CancellationToken` 与全局超时。
- 建议：给 `proc::run`/`net::download` 的调用约定写成"必须传 `ctx.timeout_or(DEFAULT)`"；新增工具时在 code review 检查；补充 `bounded_parallel_map` + `CancellationToken` + 超时的组合测试（不新增 API）。
- 验收：新增测试用 `proc::run` 跑一个 sleep 命令并在 `--timeout 1` 下返回 `TIMEOUT`（或工具约定的 1）；中断仍返回 130。
- 估级 S ｜ 优先级 P1

### 2.7 路径与配置目录解析 —— 缺失

- fcmd：`infras/fs.py`（303 行）提供路径规范化/相对路径；`FCMD_HOME` **只用于 GUI 界面状态**（`gui/config.py:33-34`、`gui/theme.py:461`，`${FCMD_HOME:-~/.fcmd}/ui/`），CLI 无 state/cache 目录。
- 现状证据：`runtime/fs.rs:153` `normalize_path`、`:106` `temp_dir`；全仓无 `RSCMD_HOME`/`APPDATA`/`XDG` 解析，无 `config/state/cache` 目录。
- 缺口：一旦出现"下载缓存/可恢复任务/用户级配置"就没有统一落点；`--confirm` 与状态目录的权限边界未定义。
- 建议：**先 ADR 后代码**：定义 `RSCMD_HOME`（优先环境变量 → `%APPDATA%\rscmd` / `~/.config/rscmd`），子目录 `cache/ state/ logs/`，写失败返回 `CONFIG_DIR_UNAVAILABLE`（kind=runtime）。仅当第一个需要持久化的工具立项时启动。
- 验收：目录优先级单测（env > 平台默认）；只读目录下写入给出明确错误码而非 panic；`doctor` 增加目录可写检查项。
- 估级 M ｜ 优先级 P3（触发式）

### 2.8 缓存与并发/锁 —— 部分具备

- fcmd：`core/task.py:500` 行 `RunConfig`、`core/execution/` 四类执行器、`RetryPolicy`；无跨进程文件锁（全仓搜 `filelock/fcntl/msvcrt` 无命中）。
- 现状证据：`runtime/concurrency.rs:11`（`CancellationToken`）、`:55`（`bounded_parallel_map`，保序/可提前退出）；`fs.rs:71`（原子写：临时文件 + rename）；`runtime/proc.rs:38`（带超时的子进程）。
- 缺口：无进程内共享缓存；无跨进程互斥（两个 rscmd 同时写同一目标会互相覆盖，原子写只能保证"不写半个文件"）；无失效策略。
- 建议：**不做** DAG/执行器/RetryPolicy（§6-4）；只在引入下载缓存时补"目录级锁"（`create_new` 锁文件 + 超时释放），并复用原子写。
- 验收：并发 8 进程写同一缓存键，只有一个成功、其余等待或明确报错；锁文件在 panic/超时后被清理。
- 估级 M ｜ 优先级 P3（与 §2.7 绑定）

### 2.9 下载与校验 —— 已具备

- fcmd：`infras/net.py`（589 行）GET/POST/HEAD、URL 检查、下载保存、镜像测速；重试策略在任务图侧。
- 现状证据：`net.rs:39` `download`、`:66` `download_resume`（Range 断点）、`:114` `sha256_hex`、`:121` `verify_sha256`、`:138` `DownloadError`；支持 `file://`/`http(s)://`；已有本地 `TcpListener` mock 测试（P0-2 补齐）。
- 缺口：无重试/退避、无代理配置约定、无并发分片、无缓存；`DownloadError` 未映射到统一错误码（工具侧需手写 code）。
- 建议：补 `rscmd-runtime::net::Policy { retries, backoff }`（默认 0 重试，保持现有行为），提供 `DownloadError::code()` 映射（`NET_TIMEOUT`/`NET_HTTP_STATUS`/`CHECKSUM_MISMATCH`）。
- 验收：重试次数可配且默认不重试；4xx 不重试、5xx/超时重试；校验失败码固定并在 `ERROR_CODE_KINDS` 登记。
- 估级 M ｜ 优先级 P2

### 2.13 doctor 检查项 —— 部分具备

- 缺口：(a) 无 sdist；(b) 无版本号 bump 工具（当前手改 `Cargo.toml` + `CHANGELOG.md`，易漏）；(c) wheel 未做 `pip install` 后的**三平台**冒烟（`wheel-smoke` 只在本机）。

- 验收：三平台 wheel job 都执行安装冒烟并通过；版本 bump 后 `version-check` 直接通过（当前需手工确保 CHANGELOG 段落存在）。

## 3. 工具集对照

fcmd 全量工具清单见附录 A（11 类、约 90 个模块；另有 14 个 GUI 应用不在对照范围）。rscmd 现有 3 个：`case`（文本大小写）、`wc`（文本统计）、`json_fmt`（JSON 格式化）。

分类原则（按顺序取交集）：
1. **小模型高频**：模型一次调用能说清、结果可机读、失败可自解释；
2. **零/低依赖**：优先用已在 workspace 的 `serde_json/sha2/urlencoding/reqwest/schemars`，新增 crate 必须过 §5-D1；
3. **跨平台一致**：Windows/macOS/Linux 行为一致，不依赖 GUI、注册表、shell；
4. **无破坏性与无凭证**：不做删除/覆盖/任意命令执行/凭据读取。

## 5. 需要拍板的决策点

> 以下任一被采纳都会改变对外契约或流程，**未经确认不落代码**。已落地但需要你确认口径的，标注"已落地"。

| ID | 决策 | 选项 | 影响面 | 建议 |
|---|---|---|---|---|
| D1 | 新增 crate 的准入标准 | (a) 只允许零依赖手写；(b) 允许知名 crate（`regex`/`csv`/`time`/`zip`），每个都要过 `cargo deny` + 体积评估；(c) 不设限 | 二进制约 2MB 起、构建时间、供应链 | **选 (b)，逐 crate 审批**；`zip`/`yaml` 单列 |
| D2 | `--timeout` 语义（已落地） | 秒、0=不限制、无 `--timeout-ms` | CLI 语义 | 维持现状即可；若模型需要亚秒级再加 `--timeout-ms`（新增不破坏） |
| D3 | `--log-file` 格式 | NDJSON（推荐）/纯文本 | 新参数 + 隐私（路径脱敏） | 采用 NDJSON，默认关闭，`--log-file` 才写 |

| D6 | 发布流程 | (a) 维持"手改 Cargo+CHANGELOG"；(b) 引入 bump 工具；(c) 加 sdist | 发布节奏、CI | 先做 (c) 之外的最小项：三平台安装冒烟；(b) 视发布频率再定 |

## 6. 不照搬清单（沿用，共 8 项）

1. 动态工具发现 + `_manifest_data` 指纹快路径 + 懒加载（rscmd 是静态注册表单二进制）。
2. 每工具一个 console script + Typer/argparse 签名投影（clap + schemars 已是单一事实源）。
3. Rich 表格/Unicode 检测/彩色排版作为默认输出（stdout 契约优先）。
4. DAG/任务执行器/RetryPolicy 全家桶（工具间无依赖图）。
5. MCP adapter（635 行，含资源与提示词体系）；确有需求时只做 schema 薄封装。
6. 集中配置中心/XDG 体系（fcmd 自身 CLI 也没有；先 ADR 再落地）。
7. tox / pre-commit(prek) / 多远程 push 流程（rscmd 用 xtask 单入口已覆盖等价校验）。
8. Python 侧重复维护的元数据与参数清单（schemars + `schema-check` 唯一事实源）。

## 7. 风险与开放问题

1. **并行写入**：文档写作期间曾观察到另一会话同时修改 `registry.rs`/`dispatch.rs` 并提交（69fa20a/665b1af/2ded8e8）。本文件结论已按入库状态复核；但**本方案执行前需确认同一工作区没有第二个会话在改同一批文件**，否则 R1 与工具批次会互相覆盖。
2. **覆盖率边际**：`rscmd-runtime/net.rs` 已补到平均线以上，但新增工具若只做 happy path，TOTAL 会被拉低；每个新工具都必须带失败分支用例（阈值 95% 不降）。
3. **依赖体积**：D1 若放开 `zip`/`yaml`，release 二进制与 wheel 体积会明显增长，需在 R4/R6 前实测并记录数字。
4. **Windows 一致性**：`path`/`filesearch`/`filedate` 必须用 `cfg(windows)` 与 `cfg(unix)` 双分支测试，CI 三平台都要跑，不接受"仅在 Linux 验证"。
5. **安全边界**：不引入 `taskkill`/`setenv`/`sshcopyid` 这类任意执行能力；`archive` 只做创建不做解压到任意路径（防 zip-slip）。
6. **文档生成物**：新增工具必须跑 `cargo xtask gen-schema` + `gen-docs` 并随代码提交，否则 `check-fast` 失败（`docs_check`/`schema_check` 是硬门禁）。
